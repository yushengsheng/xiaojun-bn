# xiaojun-bn

Binance 自动化工具（Tkinter GUI）。

## 当前页面结构

- **交易所批量**：原有功能页（保持兼容）
- **链上**：新增子页面，迁入独立链上批量模块（EVM）

> 两个页面配置与数据隔离，不互相覆盖。

## 交易所批量页使用说明

### 账号选择与预购买 BNB

- 账号列表最左侧的勾选决定账号是否参与本次批量任务。
- “预购 BNB”列是独立的单账号开关：勾选才会为该账号执行预购，不勾选不会预购。表头复选框可对当前账号批量全选或全不选。
- 预购只在本次批量确认中启用、配置金额大于 `0`，且该账号的预购框已勾选时执行。重试失败账号时会按稳定账号标识恢复原选择，不依赖内存对象 ID。
- 预购使用交易对的计价币。例如 `XPLUSDC` 使用 `USDC` 购买 BNB；下单后会再确认现货 BNB 可用余额。
- 预购覆盖现货市价、挂单、溢价挂单和分仓挂单。“剩余 BNB 停止”的市价模式即使页面轮次为 `0` 也支持预购。合约、理财、闪兑和普通现货 `0` 轮单次兑换不执行预购。

### 股票自动限价

- 交易类型选择“股票”，填写美股代码和轮次；买入按卖一加一个价格步长，卖出按买一减一个价格步长。买入和卖出确认完成才计一轮。
- 支持单账号和批量账号。开始前自动将现货账户可用 USDC 全部划转到资金账户，确认到账后买入；所有轮次统一使用资金账户，无需选择账户。API 未启用“允许通用划转”且划转明确被拒绝时，资金账户已有 USDC 足够则继续交易，不足则提示自行准备资金。合约、理财和冻结余额不参与归集。
- 每轮金额留空使用任务启动时分配的可用预算，填写金额则使用固定预算（含费用预留）；后续资金不足会停止。任务恢复或后续轮次不会重复归集新入账资金，卖出款和未使用款均留在资金账户。
- 只使用已有 USDC，不自动兑换 USDT；USDC 不足时直接提示。划转意图和回执会持久保存；无法确认结果时按失败处理，当前操作额外重试一次，第二次仍失败则结束当前账号。股票买单显式关闭代币化，不调用 bStocks 铸造接口，也不自动签署股票协议。
- “交易设置”包含价格步长、成交检查/改价间隔、等待上限、最大价格偏离、最大盘口价差和轮次间隔。价格步长须核对币安该股票参数；当前下单接口最多支持两位小数，数量步长不会用作价格步长。报价可能滞后，自动限价不保证秒成交。
- 盘前盘后及隔夜按股票支持情况执行；盘外不支持碎股时使用整股，隔夜保守使用整股。标准美股休市日和提前收市时段会拦截下单；交易所临时休市或维护仍以订单状态为准。
- 股票任务持久保存成交量和订单标识。撤单回执不算撤单完成，确认原单终态后才按剩余股数重挂；只卖本任务买入股数，不卖原有持仓。停止、超时和失败时先清理任务订单与持仓，无法清理时显示残余并保留恢复记录。恢复未完成任务需使用原设置。
- 股票模式不自动提现。公开股票 API 未提供独立可卖持仓查询，本功能按自身订单成交记录计算持仓，并由股票下单接口校验实际可卖量；运行期间请避免同时手动操作同一股票。未进行实盘验收。

### 现货模式与停止方式

- 市价模式的停止方式为二选一：
  - **现货轮次**：保持原有逻辑，配置多少轮就执行多少轮。
  - **剩余 BNB**：不使用现货轮次作为上限，每轮检查 BNB 余额，低于设置阈值时停止。
- 分仓挂单行情轮询间隔为 `1.5` 秒。手动点击停止，或触发剩余 BNB 阈值时，都会先撤销该任务挂单，再将可交易的基础币市价卖成计价币。程序会复查未完成挂单和可交易仓位，确认清理成功后才报告结束；失败则显示明确的清理异常。
- 所有现货模式的到账检测都允许“交易对任意一方有仓位”后开始。例如账号只有 `ALLO` 而没有 `USDT`，`ALLOUSDT` 分仓挂单可以直接从卖单开始。
- 批次共享的 API 限流等待同时适用于现货市价、挂单、溢价挂单、分仓挂单、合约和理财请求，等待期间仍可停止任务。
- 自动分仓挂单的“策略设置”弹窗可复制分享或从剪贴板导入 15 项行情判断参数；导入后检查并点击“保存并运行”才生效，主界面的下单参数不随之覆盖。
- 点击停止后，当前现货任务先确认撤销自身未完成订单，再将当前交易对可交易的前置币兑换为后置币；低于交易所最小交易量的尘埃会保留。合约任务会确认持仓归零。清理失败会保留状态并明确提示，停止清理会继续重试。
- 关闭窗口会等待后台任务、撤单和仓位清理，以及运行状态保存全部完成后才退出；网络中断期间保留窗口，不再按固定时间强制退出。
- 开启“市价交错执行”后，工作线程初始按奇偶分为买卖反相的两组；每个节拍会等待对应市价单确认成交后再继续。账号结束后会在节拍边界自动平衡两组，先完成已买仓位的卖出，再调整下一次买入时机；剩余两个账号仍保持交错，只剩一个时正常继续。

- “查询成交额”直接按已保存条件查询，旁边的“设置”按钮可保存起止日期，重启后仍保留；账号右键查询也复用该条件。日期均留空查近30天，只填任一日期查当天，填写两个查起止日期范围。可输入 `20260902`、`202692` 或 `2026-9-2`，自动显示为 `2026-09-02`；按北京时间包含起止日，查询今天截至启动时。成交额、手续费和买卖收支差的统计口径保持不变。

### `0` 轮兑换与交易对输入

- 交易对可输入 Binance 原生格式，也可加 `/`；程序会移除分隔符并转为大写。例如 `btc/eth` 会解析为 `BTCETH`。
- **现货 + 市价 + `0` 轮**是一次真实现货市价兑换，不走闪兑。程序会从 Binance 现货交易对中解析正向或反向路由：例如输入 `USDT/USDC`，如果交易所仅有 `USDCUSDT`，则使用该交易对买入 USDC；输入 `BTC/ETH` 时也会按交易所实际存在的正向或反向市场执行。
- 双向解析只扩展市价 `0` 轮单次兑换，不改变多轮市价和其他挂单模式的交易对方向。
- `0` 轮下单异常会标记为“0轮现货兑换”失败并立即中止后续提现，不会把未完成的兑换误报为完成。

### 错误重试与运行安全

- 交易任务遇到临时网络或服务故障会保留当前轮次、买卖步骤和订单，持续恢复后接续执行，不因达到 10 次重试就跳过或停止账号。请求失败后通常间隔 1 秒再试，请求本身耗时和交易所限流等待另计；轮次、BNB 阈值和手动停止条件继续生效。
- 交易所已移除“核对未确认”的按钮、接口和后续任务阻塞。提现、划转、闪兑、理财、现货/合约及股票操作无法确认结果时按失败处理，当前失败步骤额外重试一次；第二次仍失败则结束当前账号，同一线程继续下一个账号。已成功步骤不重跑，正常成交查询、撤单、行情保护和停止清理保持生效。失败判定不代表交易所一定未执行，重试可能重复操作。
- 链上板块按用户要求恢复到 2026-10-08 08:55 截图所示的源码交付状态（489 项门禁通过的那次），保留三天日志轮转及固定回收规则。之后新增的链上签名账本、恢复入口及广播串行锁已撤销；历史钱包、配置和账本数据不删除。链上线程继续使用该基线的界面配置。
- 现货、合约及股票订单核对检查原订单标识，不能以另一笔成交释放原任务保护。
- 中转回收的固定清理规则保留：真实回收结束后，零余额或每项余额均严格低于边际的钱包记录统一删除，无需旧第二跳记录。BNB 边际为 0.00001，USDT/USDC 各 0.0005；等于或高于边际、余额查询失败或不完整的钱包保留。其他币种无边际时仅允许零余额清理；模拟执行及手动停止不做最终删除。清理钱包不代表原付款成功。回收并发使用界面执行线程数，不再设 4 线程上限。
- 中转回收只按钱包余额执行，不检查原付款的第二跳记录。达到边际的 USDC、USDT 等代币逐个回收到指定地址，低于边际的代币跳过，最后回收 BNB 等原生币；手续费不足时保留钱包并归入待人工。只有本次实际提交的回收交易仍未确认时才保留确认保护，防止重复发送。
- 自动回收与手动回收均在广播前保存本次回收交易编号。自动回收重试沿用同一份签名交易；回复丢失、确认超时或回执编号不符时保留确认保护，后续回收及钱包复用先核对原回收交易。历史钱包仅在原网络复用，回收边际及界面线程配置不变。
- 交易所同一账号的资金提交仍按原有顺序保存及发送，不同账号保持隔离；各层嵌套调用共用一次额外重试额度。此规则仅适用交易所，不修改链上普通付款、中转及回收规则。
- 同一数据目录只能运行一个桌面实例。交易所操作记录从备份恢复后自动将无最终结果的旧资金/订单记录记为失败，无需人工解除保护；已确认股票持仓、当前任务清理及批次检查点仍保留。共享启动、加密保存和链上恢复实现不变。
- 日志界面队列有上限，磁盘仍保存全部运行日志；日志日期与时间统一使用北京时间。交易规则缓存每 5 分钟失效，提现前核对网络开关、限额、手续费和数量步长；需要 MEMO/Tag 的网络提示到交易所处理。相关字段参考 [Binance 官方钱包接口](https://developers.binance.com/en/docs/catalog/core-trading-wallet/api/rest-api/capital)。
- 交易结束后，旧单核对或仓位清理暂未成功时，原任务保留最终提现步骤并持续重试；恢复并确认清理完成后，按该任务的自动提现设置接着执行，不重新跑交易轮次。手动停止或关闭窗口会跳过提现，继续完成清理。
- Binance `-2015` 表示 API Key / Secret、账号权限或 IP 白名单与当前请求不匹配。该类明确权限错误每个请求最多尝试 `3` 次，以减少无效请求和重复日志；连续失败时应检查 API 权限、IP 白名单和代理出口 IP，而不是反复重启任务。
- 账号数据、代理配置和任务状态保存在本地 `data/`。不要将该目录、API Secret、提现凭据或完整代理链接提交到 Git。
- 启动代理前会清理本程序留下的过期运行时。Windows 通过进程 ID 存活检查和完整命令行匹配确认残留，只结束精确引用本程序过期配置的 `sing-box` / `xray` / `hysteria` 进程；正在运行的所有者和无法确认的进程会保留。
- 归集 BNB 时，账号总残留估值小于 `0.1 USDT` 视为小额尘埃，不报残留异常。

## 快速使用（Windows）

1. 从 Releases 下载 `xiaojun-bn-vX.Y.Z-windows-x64.exe`，或下载 `xiaojun-bn-vX.Y.Z-windows-x64-portable.zip`
2. 双击运行，无需本机安装 Python、交易所模块依赖、代理模块依赖、链上模块依赖、UI 运行依赖
3. 首次运行会在程序同目录自动创建 `data/`，用于保存本地配置与链上页面数据

> Windows Release 已内置主程序运行环境，以及交易所、代理、链上、UI 所需运行依赖；同时内置 `xray`、`sing-box` 与官方 `Hysteria` 客户端，SS 和 Hysteria2 代理在其他电脑上也可直接使用。

## 源码运行

### Windows

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python 小军bn.py
```

可选自检：

```powershell
.\.venv\Scripts\python 小军bn.py --selftest
.\.venv\Scripts\python 小军bn.py --selftest-online
```

- `--selftest`：离线完整性自检，适合本地排查或发布冒烟验证
- `--selftest-online`：额外验证 ETH/BSC 公网 RPC 可达性，适合手动联机排查

### macOS（本地启动）

- 无终端窗口：`小军bn一键启动.app`
- 备用脚本：`一键启动.command`
- 启动脚本：`launch_no_terminal.sh`
- 启动日志：`data/logs/startup.log`
- 链上运行日志：`data/logs/onchain_runtime_YYYYMMDD.log`；交易所运行日志：`data/logs/exchange_runtime_YYYYMMDD.log`。Windows、macOS 和 Linux 共用按北京时间每日轮转的规则，保留当天及前两天的全部记录，超过日期范围自动删除；不按大小或启动次数提前删除。页面仍只显示最近 500 行，关闭程序后磁盘日志保留。旧客户端需升级或从更新后的源码重新启动才能生效。

## 依赖

- 基础：`requests`
- 安全存储：`cryptography`
- 链上模块：`eth-account`、`eth-utils`

- 源码运行前请使用 `requirements.lock` 安装带哈希校验的依赖
- macOS 一键启动脚本会在启动前按需自动安装依赖
- 建议源码运行使用项目内 `.venv`，避免全局 Python 依赖冲突影响交易所、链上或打包自检
- 发布回归会审计运行锁和构建锁中的已知漏洞；本地完整回归请按 `requirements-build.lock` 安装依赖
- 若通过 `SING_BOX_PATH` 指定外部 `sing-box`，可同时设置 `SING_BOX_EXECUTABLE_SHA256` 为该可执行文件的 SHA-256；项目内已认证缓存和随包运行时会优先于普通 `PATH` 程序
- 交易所与链上代理框支持完整 `hy2://` / `hysteria2://` 分享链接；`pinSHA256` 证书指纹会原样交给官方客户端校验，并启用 Hysteria2 Fast Open 降低新连接延迟
- 代理框旁的按钮每次点击都会重新请求对应业务接口，并显示 `延迟 N ms`；连接失败时显示 `失败`

## 链上动态估费

- 链上任务启动时固定模式、网络、币种和金额等参数；运行中修改界面配置只影响后续任务。
- 金额和等待时间拒绝 `NaN`、无穷大等非有限值。执行线程及 nonce 并发最多 128，receipt 重试最多 1000 次，等待参数最多 86400 秒。

- ETH / BSC 转账使用最近 20 个区块的费用历史：取各区块按 gas 用量加权的 P50 优先费，再取跨区块中位数，加上下一块基础费并留 10% 余量；最终报价不低于节点建议价。
- 同网络并发任务共享最多 3 秒的报价；中转第一跳发送前也会刷新报价并重新检查余额。历史查询最多等待 8 秒，节点请求失败会尝试备用节点；历史数据不可用时回退节点建议价并记录警告。
- 仅影响新签名的交易，不会自动加价替换已提交交易；拥堵时不能保证立即确认。转账金额、收款地址和中转流程保持不变。

## Linux 交易所服务器

Linux 版通过 HTTPS 网页管理交易所账号、策略、参与账号与任务启停，实时显示运行及报错日志。界面和账号导入、右键菜单、操作确认沿用桌面逻辑。服务器独立运行，本地电脑关机不会停止已启动的任务；服务器重启后需重新解锁。桌面版继续支持交易所和链上板块，Linux 版只支持交易所。

新服务器支持 Ubuntu 24.04、Debian 12/13 x86_64、Python 3.11+ 和 systemd。开放面板端口（默认 TCP 26483）及自动证书验证 TCP 80，将下面的 `公网IPv4` 替换为服务器地址：

```bash
curl --proto '=https' --tlsv1.2 -fL https://github.com/yushengsheng/xiaojun-bn/releases/latest/download/install-linux.sh -o install-linux.sh && sudo bash install-linux.sh --host 公网IPv4
```

没有 `curl` 时先运行 `sudo apt-get update && sudo apt-get install -y curl`。无需域名或付费服务；也可使用 `--host 完整域名`。`--port` 可改面板端口，`--backend-port` 可改仅本机监听的内部端口；`--check` 只执行预检。自备证书使用 `--tls-cert 完整证书路径 --tls-key 私钥路径`，无需 TCP 80，由原证书工具负责续期。

安装器会校验发行包和代理内核哈希，使用独立目录、服务账号及 nginx，拒绝覆盖已有安装或占用端口。安装成功后在服务器读取初始化码，在网页设置自己的程序密码；不会迁移本地账号或自动开始交易。请勿在已有交易服务器重复安装。

服务自动清理缓存、轮转日志并限制资源使用，账号与未完成订单记录保留。详见 [Linux 运行说明](linux_exchange/README.md)。

## 回归检查

macOS 源码改动后使用固定入口运行完整回归：

```bash
python3 tools/run_full_regression.py
```

该入口使用项目内 `.venv-regression`。首次运行或依赖锁变化时会按
`requirements-build.lock` 自动重建，后续直接复用，不依赖会被系统清理的临时目录。

Windows 可在已安装构建锁依赖的项目虚拟环境中运行：

```powershell
.\.venv\Scripts\python tools\run_regression.py --gui
```

需要额外验证公网 RPC 时再加 `--online`。如果只是确认当前 Python 环境是否隔离，可运行：

```powershell
.\.venv\Scripts\python tools\check_python_environment.py
```

## 账号导入格式（交易所批量页）

- 支持 2 段一组：`APIKEY` / `APISECRET`，未提供提现地址时自动跳过该账号的所有提现步骤
- 继续支持 3 段一组：`APIKEY` / `APISECRET` / `提现地址`
- 支持同一行使用空格、Tab 或 `|` 分隔
- 支持行尾备注文本（会自动忽略）
- 支持剪贴板粘贴导入（按钮或 `Ctrl+V`）
